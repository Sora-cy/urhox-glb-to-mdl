# 故障字典（按症状查）

每条都是实测定位过的，含"判断依据"和"已排除的假线索"。

---

## 1. 引擎解析阶段直接挂死（日志停在"开始解析 xxx"，验证 TIMEOUT）

**二分实验已做全，边界很清楚，别再试：**

| 配置 | 结果 |
|---|---|
| 自己的顶点 + 现役骨架数值 | ✅ 加载 |
| 自己的骨骼名 + 现役 121 字节数值 | ✅ 加载 |
| 自己的 pos/rot/scale + 现役 offset | ✅ 加载 |
| 自己的骨架 + offset 全单位矩阵 | ✅ 加载 |
| **任意一套"完整自建骨骼数值"**（重算 offset / 扁平化层级 / 补 bbox+radius / 补齐骨数） | ❌ **全部挂死** |

**结论**：用自己的骨架数值必挂，原因未明（IBM 与骨骼世界变换字节级自洽、互乘偏差 0.00000、
四元数顺序也正确）。**唯一可行路线 = 借现役骨骼段**，也就是 `retarget.py` 的做法：
只把顶点重定向过去，骨骼段整段照抄现役模型的字节。

## 2. 腿被撕断：膝盖以下断开、只剩正面一点连着、脚掌没厚度

**原因**：预蒙皮写成 `v' = Σ wᵢ·Aᵢ⁻¹·v`。引擎静止时算的是 `Σ wᵢ·Aᵢ·v'`。
**这两个算子不可交换**——在关节权重过渡带（≈50/50）还原不回去，误差可达 **0.19**
（而模型身高才 1.0）。

**判断**：`retarget.py` 会打印 `静止还原误差：最大 …`。**> 0.01 就是这病**。

**处理**：对**混合矩阵**求逆：

```python
M = Σ (wᵢ / Σw) · Aᵢ        # 先混合
M[3] = (0, 0, 0, 1)
v' = inv(M)[:3,:3] @ v + inv(M)[:3,3]
法线 = M[:3,:3].T @ n        # 逆转置
```

修好后误差应为 **0.0000**。

⚠️ 若把左右腿摆动互换、故障**跟着"后摆的那条腿"走**，说明不是单侧网格问题
（左右几何/权重/绕序实测全对称，不要去镜像左腿）。

## 3. 模型躺倒：没头 / 身上有洞 / 胯部撕裂 / 螃蟹横着走

**原因**：把顶点当成 Z-up 做了 -90°X 旋转。**两边都是 Y-up**，不该有任何旋转。

**判断**：包围盒 `size = (X≈1.84, Y≈0.375, Z≈1.90)` → 身高跑到 Z 轴 = 转错了。
正常应为 `(0.38~0.97, 0.998, 0.19)`。

**处理**：`retarget.py` 只做等比缩放 + 抬脚底到 y=0，**不做旋转**。

## 4. 怪物几乎不动 / 只有一条腿有点动作

**原因**：afk-rig 的自动权重把约 41% 全给 `spine_03`，双腿合计 9%，
`L_Calf`/`L_Foot` 接近 0，且左右不对称。

**处理**：跑 `reweight.py`（按骨骼线段距离 1/d⁴ 重算，取 top4，剪掉 <2%，
外加"踝以下确定性归同侧脚骨"的兜底）。修好后 spine 降到约 17%、双腿约 15% 且左右对称。

---

## 5. T-pose 举着手进游戏

**原因**：绑定姿势就是 T-pose，游戏里的姿态驱动只压 -35°/-42°，不够。

**处理**：`lower_arms.py` 在绑定姿势里烘焙手臂下垂 65°。校验：网格 X 宽度应明显收窄
（实测 0.967 → 0.380）。

---

## 6. 引擎读到 0 骨骼 / 骨骼名乱码

- **0 骨骼** → GLB 没蒙皮（`afk-rig export` 之前忘跑 `bind`），或转换时骨骼段没写
- **从第 2 根起名字乱码** → 骨骼条目长度算错，必须是 `名字 + null + 121`

---

## 7. 加载成功但高度不对（巨大 / 极小）

引擎对本管线产出的 `.mdl` 自算包围盒可能只有 0.049（真实 1.9），归一化系数会爆炸几十倍。

**处理**：在配置里显式填 `height = 0.998`（**模型自身空间的身高**，不是世界身高）。
换基底模型时必须按新基底的实际身高改。

---

## 8. 某个部位被劈开 / 消失，只看到正面

**原因**：单面薄片 + 背面剔除。AI 生成的模型顶点基本不焊接（实测 564 个连通块），
布片是单面几何。

**处理**：材质设 `CULL_NONE`（双面）。

⚠️ **本地软渲染器不分正反面**（画家算法 + `abs(法线)` 着色），所以本地预览图看不出这问题，
不要拿本地图反驳这条。

---

## 9. 贴图满身错位斑块

**原因**：没贴图时会回退套用别的模型的贴图，两套 UV 完全不同。

**处理**：无贴图就走灰模（中性浅灰 + 粗糙度 0.72）。模型自带贴图的话，
从 GLB 的 `images` 里提取 baseColor / normal / metallic-roughness，压到 1024/1024/512。
实测 **UV 不需要翻转 V**。

---

## 10. 验证 `load phase FAIL + TIMEOUT`，但资产没动过

**先查 Lua 语法**，症状完全一样。典型是把注释/表头插进了表的内部导致
`unexpected symbol near '}'`。改完配置表**立刻**看一眼结构，确认 `}` 只有一个。

## 11. 已排除的假线索（不要重走）

| 曾经的怀疑 | 实测结论 |
|---|---|
| GLB 缺 `.meta` 所以引擎不认 | 补了仍是 0 骨 → **引擎根本不解析 GLB**，与 meta 无关 |
| `canvas import` 能导入模型 | 只认图片/视频 |
| 命令行有 import 子命令 | 没有 |
| 包围盒偏小导致卡死 | 显式覆盖 height 后仍卡死 → 是骨骼段问题 |
| LOD 级数不足导致卡死 | 补到 4 级 LOD 无效 |
| 顶点含 NaN/Inf | 0 个 |
| 索引 / 骨骼索引越界 | 无越界，权重和全 = 1 |
| 腿部关节高度不齐导致错位 | 对齐后脚掌反而被压扁 → `leg-blend` 必须 0 |
| 那块"薄面"是破布条 / 背面剔除 | 真因是 §2 预蒙皮不可交换；双面渲染保留但不解决问题 |

## 12. 验证方法论

**引擎离屏截图不可靠**：headless 下只拍得到加载画面（多帧截图字节数完全相同），
不能用来判断模型长相。

**本地软渲染才是主力**（几秒出图）：

- 正交三视图 + 骨架叠加：画的是文件里的原始坐标，看比例/朝向
- 姿态模拟：按游戏驱动逻辑摆骨骼 + 按 UMD2 蒙皮约定算顶点 → **这才是"游戏里实际长什么样"**
  - 用 `--swap-legs` 做左右腿对照（故障是否跟着腿走）
  - 用 `--phase` 走多帧步态看是否撕裂

**量化撕裂**：按姿态算蒙皮前后边长，报告拉伸 > 2 倍的三角面。
